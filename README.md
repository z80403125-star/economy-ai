# ECONOMY AI

Русскоязычная платформа для каталога экономических тестов. Проект создан отдельно от исходных папок: оригиналы не перемещались и не редактировались. В `public/tests/` лежат копии HTML, CSS и JavaScript, необходимые для самостоятельной публикации каталога.

## Что уже реализовано

- Адаптивная оболочка платформы и переключение разделов без перезагрузки.
- Каталог всех 10 проверенных викторин: поиск, категории, открытие отдельной копии и копирование ссылки.
- Число вопросов считывается из `script.js` каждого теста, а не задано в карточке вручную.
- Регистрация и вход преподавателей по логину и паролю без сбора почты; старые аккаунты могут входить по прежнему email.
- Профиль показывает фактический статус из Supabase; новая регистрация получает статус «Ожидает одобрения».
- Серверная точка ИИ-помощника проверяет сеанс и роль, ограничивает длину запросов и требует настроенный лимитер Upstash.
- ИИ-помощник отвечает через серверный провайдер по произвольным учебным вопросам одобренных аккаунтов.
- Генератор тестов создаёт вопросы с вариантами, правильными ответами и пояснениями для одобренных преподавателей и администраторов.
- Панель администратора показывает логины, позволяет одобрять заявки, блокировать и восстанавливать доступ, а также задавать временный пароль.
- Миграции Supabase для начальной схемы и перехода на логины.
- Статистика без тестовых или выдуманных чисел.

## Что пока не подключено

Назначение тестов ученикам, защищённая передача ответов, серверная проверка баллов, кабинет преподавателя, управление лекциями, сохранение попыток и отчётная статистика ещё не реализованы. Разделы, не подключённые к данным, явно помечены в интерфейсе.

**Не назначайте ученикам тесты как оцениваемые задания до следующего этапа интеграции.** В исходных викторинах правильные ответы находятся в клиентском JavaScript. Для соблюдения требования о скрытых ответах нужно подготовить отдельный адаптер/версию каждого теста и передавать ответы серверу на проверку. Текущие копии сохраняют исходное поведение и внешний вид, но не обеспечивают защиту ключа от просмотра.

## Запуск локально

Требуется Node.js 20 LTS или новее.

1. Откройте терминал в папке `ECONOMY-AI`.
2. Установите зависимости:

   ```sh
   npm install
   ```

3. Проверьте встроенные тесты каталога и подключение ресурсов:

   ```sh
   npm run check:catalog
   ```

4. Запустите режим разработки:

   ```sh
   npm run dev
   ```

5. Для production-сборки выполните:

   ```sh
   npm run build
   ```

`npm run dev` поднимает только интерфейс Vite. Для проверки входа по логину, административного сброса паролей и ИИ запустите проект через Vercel CLI (`vercel dev`) после настройки переменных окружения.

## Подключение Supabase

1. Создайте проект в Supabase и дождитесь завершения подготовки базы.
2. Для нового проекта откройте **SQL Editor → New query** и выполните `supabase/migrations/001_initial_schema.sql`. Для существующего проекта с уже применённой начальной схемой выполните только новую миграцию `supabase/migrations/003_username_auth.sql`; она добавит логины существующим профилям.
3. В **Project Settings → API** скопируйте Project URL и публичный `anon`/publishable key.
4. Создайте локальный `.env` на основе `.env.example` и укажите:

   ```env
   VITE_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
   VITE_SUPABASE_ANON_KEY=ВАШ_ПУБЛИЧНЫЙ_ANON_KEY
   VITE_AUTH_API_URL=https://ВАШ-ПРОЕКТ.vercel.app/api/auth/login
   VITE_ADMIN_RESET_API_URL=https://ВАШ-ПРОЕКТ.vercel.app/api/admin/reset-password
   SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
   SUPABASE_ANON_KEY=ВАШ_ПУБЛИЧНЫЙ_ANON_KEY
   SUPABASE_SERVICE_ROLE_KEY=СЕКРЕТНЫЙ_SERVICE_ROLE_KEY
   UPSTASH_REDIS_REST_URL=...
   UPSTASH_REDIS_REST_TOKEN=...
   ```

   `VITE_SUPABASE_ANON_KEY` и `SUPABASE_ANON_KEY` — публичный ключ Supabase. `SUPABASE_SERVICE_ROLE_KEY` — строго серверная переменная: не добавляйте к ней префикс `VITE_`, не вставляйте её в React-код и не публикуйте. Адреса `VITE_AUTH_API_URL` и `VITE_ADMIN_RESET_API_URL` должны указывать на серверные функции Vercel; URL GitHub Pages сам по себе API не запускает.

5. В **Authentication → Providers → Email** отключите **Confirm email**. Регистрация использует технический внутренний адрес на домене проекта Supabase, который не показывается и не запрашивается у преподавателя, поэтому подтверждение по письму не используется.
6. После регистрации профиль остаётся `pending`, пока администратор не одобрит его. Вход по логину выполняется через `/api/auth/login`, который ограничивает попытки через Upstash.
7. Роль администратора назначается только доверенной процедурой. После создания аккаунта администратора владелец проекта может выполнить в SQL Editor запрос, подставив точный UUID этого пользователя:

   ```sql
   update public.profiles
   set role = 'admin', status = 'approved'
   where id = 'UUID_ПОЛЬЗОВАТЕЛЯ';
   ```

   Не добавляйте назначение роли администратора в открытую форму регистрации.
8. Сброс пароля выполняется из панели администратора: администратор назначает временный пароль и сообщает его пользователю по безопасному каналу. Серверная функция `/api/admin/reset-password` использует `SUPABASE_SERVICE_ROLE_KEY` только на сервере.

## Подключение ИИ

Точка `/api/ai/chat` работает как серверная функция Vercel. Для неё требуются:

- `OPENAI_API_KEY` — серверный API-ключ провайдера;
- `OPENAI_MODEL` — необязательное имя доступной модели;
- `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` для проверки преподавателя;
- `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` для ограничения частоты запросов.

Серверные функции входа и сброса пароля также используют `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`; вход дополнительно требует `SUPABASE_ANON_KEY` и Upstash для ограничения попыток. Для GitHub Pages задайте переменные репозитория `VITE_AUTH_API_URL` и `VITE_ADMIN_RESET_API_URL` как полные URL соответствующих endpoints на Vercel. Workflow передаёт эти переменные в сборку. В Vercel задайте `AI_ALLOWED_ORIGIN=https://z80403125-star.github.io`, чтобы разрешить запросы с опубликованного сайта.

Добавьте серверные переменные в локальный `.env` и в **Vercel → Project Settings → Environment Variables**. Для GitHub Pages также настройте переменную репозитория `VITE_AI_API_URL` как полный URL endpoint, например `https://ВАШ-ПРОЕКТ.vercel.app/api/ai/chat`; workflow передаст её в сборку. В Vercel задайте `AI_ALLOWED_ORIGIN=https://z80403125-star.github.io`, чтобы разрешить запросы с опубликованного сайта. GitHub Pages не запускает функции из каталога `api/`, поэтому без отдельного Vercel deployment ИИ-помощник работать не будет. Без обязательных серверных настроек API возвращает понятную ошибку, а не имитирует ответ ИИ. Лимит сейчас — 15 обращений на аккаунт в минуту.

## Публикация через GitHub и Vercel

1. Создайте GitHub-репозиторий и добавьте в него содержимое только папки `ECONOMY-AI`.
2. Проверьте, что `.env` не попал в коммит. Публичный ключ Supabase допустим на клиенте; секретные ключи — нет.
3. В Vercel выберите **Add New → Project**, импортируйте репозиторий и оставьте корневой каталог проекта.
4. Добавьте переменные окружения из разделов выше для Production и Preview.
5. Нажмите **Deploy** и проверьте каталог, открытие тестов, вход и серверный endpoint после подключения сервисов.

Оригинальные папки на Desktop остаются независимыми. Копии, включённые в этот проект, находятся в `public/tests/`; при изменении оригинала для публикации нужно обновить соответствующую копию и повторно выполнить `npm run check:catalog`.

## Технологии и структура

- React, Vite, JavaScript и CSS.
- Supabase Auth, Postgres и Row Level Security.
- Vercel Serverless Function для серверного ИИ-запроса.
- Upstash Redis для лимитирования ИИ-запросов.

Основные каталоги: `src/components/`, `src/pages/`, `src/auth/`, `src/services/`, `src/data/`, `api/`, `supabase/migrations/`, `scripts/` и `public/tests/`.
